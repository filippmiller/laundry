# Laundry — Чисто

Сервис стирки, глажки и химчистки с забором и возвратом вещей из многоквартирных домов. Два тарифа: **Эконом** (мешок, пломба, вес) и **Защищённый** (поштучная опись, состояние, доказательства).

**Статус (на 2026-11-19):** проверенный pre-pilot / демонстрационный вертикальный срез (`b6ae600`), прошедший двойной независимый cold red-team аудит (`pro` + OpenAI Codex `gpt-6.2-sol`, 20/20 P0/P1 замечаний закрыто). Внешние провайдеры (SMS, эквайринг, 54-ФЗ ККТ/ОФД, геокодинг/маршрутизация, off-host DR) и юридические гейты требуют решений владельца перед реальным запуском.

## Что уже работает
- PostgreSQL-схема из 12 групп + SQL-триггеры append-only, legal hold sync и баланса журналов (**83 таблицы, 25 миграций `0000`–`0024`**).
- Тенантная авторизация из серверной сессии, RBAC/ABAC на уровне маршрутов и сервисов, проекции полей по роли, CSRF/Origin на всех небезопасных методах (`POST`/`PUT`/`PATCH`/`DELETE`), демо-вход только вне production.
- Атомарные брони слотов с `safety_buffer_orders`, expiry-worker, сверка и ремонт ёмкости с аудитом.
- Калькуляция immutable-квот, заказ, бронирование только привязанных слотов, отмена с освобождением ёмкости и перенос брони одной транзакцией, корректная привязка `termsVersion`.
- Идемпотентность всех мутаций с привязкой ключа к актору и `replayGuard`; лимиты частоты (`@fastify/rate-limit`, общий, вход, вебхуки).
- Приёмка курьером (мешок/пломба/вес, офлайн-синк сканов, привязка доказательств к заказу), приёмка прачечной с расхождениями, обработка, полный QC, точная выдача комплекта, частичная доставка с повторным визитом и восстановлением, претензии с `evidence_legal_holds` (включая повторное открытие).
- Двойная запись в журнал, фиктивный платёжный адаптер с блокировкой повторного capture, доплатным счётом при уже оплаченном основном и возвратами, подписанный вебхук-inbox с per-event транзакциями и возвратом зависших `processing`-лизов, chargeback-статус, партнёрские начисления (с сверкой фактического веса и аннулированием при возврате без обработки), двойной контроль выплат и споры.
- Outbox-воркер с экспоненциальным backoff, dead-letter и возвратом зависших `processing`-лизов; `SIMULATION_ONLY`-гейт маршрутизации.
- Курьер: офлайн-очередь сканов в IndexedDB, привязка устройства к курьеру, пересчёт хеша события, проверка контейнера и пломбы по заказу, автозавершение pickup-стопа при передаче прачечной.
- Поддержка: обращения клиента по заказу, ответы поддержки, закрытие; отзывы по завершённым заказам, лайки и модерация с аудитом; приватный экспорт данных.
- Администрирование: участники и роли с аудитом и защитой последнего активного администратора, отзыв сессий, журнал аудита и очередь антифрод-сигналов (только просмотр).
- Fastify API с Zod-валидацией и генерируемым OpenAPI 3.1 (проверено на синхронность с фронтендом); React SPA с ленивой загрузкой рабочих мест клиента, курьера, прачечной, диспетчера, поддержки, финансов и администрирования.
- 44 тестовых файла (`unit` + PostgreSQL + HTTP API + межролевые и adversarial-сценарии + регрессии Wave 4B), браузерный smoke-тест (`11/11`) и визуальная проверка mobile/tablet/print (`25/25`).
- Денежные разрезы: дебиторка клиентов, кредиторка прачечных (с учётом только `approved`/`paid` выплат), вклад до затрат курьера и экспозиции — `GET /finance/analytics`, `GET /finance/overview`, `GET /customer/finance`.
- Иконографическая сдача и приёмка (`shared/garment-taxonomy.ts`, `apps/web/src/components/GarmentPicker.tsx`), автопредложение доплаты по весу (`src/services/weight-variance.ts`), хронометраж (`GET /ops/chronometry`), повтор заказа (`GET /orders/:id/repeat`) и сигнал оттока (`GET /ops/churn`).

## Быстрый старт (Windows/local)
```bash
npm ci
npm run dev:db          # в отдельном терминале: PostgreSQL на :55432
$env:DATABASE_URL='postgres://postgres:postgres_test_only@127.0.0.1:55432/laundry'
npm run db:migrate
npm run db:seed
npm run web:build
npm run start:api       # http://localhost:3000 (SPA + /api/v1)
```
Демо-пользователи выводятся `npm run db:seed`. Вход: телефон + роль; организация берётся из сессии.
