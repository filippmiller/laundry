## 1. Executive summary

Продукт — сильная, честно написанная основа: мультиарендная изоляция, идемпотентность, ABAC по доказательствам, optimistic locking, keyset-пагинация и 129 эндпоинтов покрывают почти весь жизненный цикл заказа. **Критических (P0) дефектов нет.** Но **7 «свежих» срезов из 4 дней работают только наполовину**: половина нужных эндпоинтов существует, но не вызывается из интерфейса, а часть обязательных фоновых процессов (воркер) не входит в состав стенда — из-за чего **слоты не возвращаются, уведомления не доставляются, а новые финансовые срезы партнёра пусты**.

Топ-10 находок по влиянию:

1. **LA-01** (P1) Просроченные холды слотов **никогда не освобождают ёмкость**: `expireDueHolds` живёт только в `src/workers/index.ts`, HTTP-маршрута и кнопки нет. Проверено: `reservedOrders` 11→12, через 80 с (после TTL 1 мин) — всё ещё 12, а `/dispatch/capacity-reconciliation` показывает `[]`.
2. **LA-02** (P1) **Outbox-уведомления не доставляются вообще**: 17 из 19 типов уведомлений (заказ оформлен, слоты подтверждены, претензия рассмотрена, возврат оформлен, доставка не состоялась, брак на ОТК) рождаются только в воркере. `/ops/metrics` показывает `pendingOutbox: 316`, у клиента в ленте только 2 типа.
3. **LA-05** (P1) **Партнёр не видит свои выплаты, кредит-ноты и споры** — `/finance/partner-payouts` и `/finance/partner-credit-notes` для него дают 403, партнёрского эквивалента нет, спор может открыть только роль `partner_finance`, которой **нет ни в одной демо-персоне**.
4. **LA-04** (P1) **Курьер выдумывает объявленную ценность вещи**: дефолт `declaredValueRub: "5000"` (5000 ₽) на каждую вещь, тогда как лендинг обещает «объявленная ценность» и «прозрачное согласование доплат», а котировка содержит только `subtypeId + quantity`.
5. **LA-03** (P1) **Тред поддержки закрывается навсегда**: эндпоинта переоткрытия нет (в отличие от претензий), а `postMessage` в закрытый тред → `INVALID_TRANSITION`.
6. **LA-08** (P2) Демо-стенд **не наполняет финансовые срезы партнёра**: `partner-payouts` и `partner-credit-notes` возвращают `{items: []}`, в `partner/accruals` — `invoices: []`. Новый срез нельзя увидеть, не нажав вручную «Начислить партнёру».
7. **LA-10** (P2) Лендинг обещает **«отдельный стоп за +500 ₽»**, но в форме заказа нет ни одного поля `offSchedule*` — API их поддерживает, UI — нет.
8. **LA-07** (P2) **Сверка смены курьера пропадает в момент закрытия**: `GET /courier/shifts/:id/reconciliation` не вызывается из UI, а `setShift(null)` теряет `shiftId`; поздние офлайн-сканы ложатся в `shift_reconciliation_adjustments` и не видны никому.
9. **LA-12** (P2) **Экспорт персональных данных и управление сессиями есть только у клиента** — у курьера, диспетчера, поддержки, финансиста и админа нет ни одного экрана, хотя эндпоинты `/me/privacy-export` и `/auth/sessions` доступны всем.
10. **LA-18** (P2) **11 «сиротских» эндпоинтов** без единого UI-вызова (`/courier/shifts/:id/reconciliation`, `POST /finance/partner-disputes/:id/resolve`, `/finance/fiscal-receipts`, `/partner/expected-receipts`, `/dispatch/pickup-queue`, `/service-areas/resolve`, `GET /quotes/:id`, `POST /slots/holds`, `GET /evidence/:id`, `GET /admin/members/:id/roles`, `POST /auth/preview-unlock`).

**Быстрые победы (S, 1–2 дня):** (а) запустить/встроить воркер в стенд и в деплой — снимает LA-01 и LA-02 разом; (б) добавить в админку кнопку «Прогнать outbox» и «Протухшие холды» — снимает LA-01/LA-02 без воркера; (в) показать ключ предпросмотра в UI — снимает LA-16; (г) убрать «(@zxing)» из кнопки и дубликат роли из 403 — LA-20/LA-21; (д) добавить в демо-сид partner-invoice + спор + кредит-ноту — снимает LA-08 и открывает LA-05/LA-11 владельцу.

### 3б. Пять главных сквозных сценариев, которые чинить в первую очередь

1. **Клиент оформляет заказ → курьер забирает → фабрика обрабатывает → клиент получает вещи и уведомления.**
   Сегодня ломается в двух местах: клиент не получает ни одного уведомления о событиях заказа (LA-02), а курьер подставляет ценность вещи, которую не заявлял клиент (LA-04). Сценарий «работает», но обещание «я в курсе своего заказа» не выполняется.
2. **Партнёр отработал месяц → финансист начисляет → партнёр видит цифру → спор → кредит-нота → выплата.**
   Сегодня обрывается на шаге 3: партнёр видит только оценку, не обязательство (LA-05); шаг «спор» непроходим из демо и из UI (LA-11), а «разрешить спор» вообще не имеет UI (LA-18). Это самый дорогой сценарий платформы, и он сейчас ненаблюдаем.
3. **Курьер открывает смену → берёт точки → закрывает смену → сверка.**
   Работает, но сверка умирает в момент закрытия (LA-07), а брони, которые клиент не оформил, безвозвратно съедают ёмкость (LA-01).
4. **Клиент открывает претензию → поддержка отвечает → решение → компенсация → клиент узнаёт результат.**
   Работает, кроме уведомлений (LA-02) и невозможности продолжить закрытый тред (LA-03). Поддержка теряет черновики (LA-09).
5. **Администратор проверяет, что система жива: роли, аудит, метрики, очереди.**
   Видно счётчик `pendingOutbox: 316`, но нет ни кнопки «доставить», ни кнопки «протухшие холды» (LA-01, LA-02); PII-чтения не журналируются (LA-13). Оператор видит симптом, но не может его снять.

### 3в. Вопросы владельцу по бизнес-правилам (не решаю сам)

1. **Воркер обязателен в релизном контуре?** Если да — как он попадает в деплой (systemd/ отдельный контейнер/ cron)? Если нет — нужен ли ручной «дренаж» из админки? (LA-01, LA-02, LA-24)
2. **Кто и как объявляет ценность вещи?** Клиент при заказе, курьер при приёмке, или прачечная при осмотре? От этого зависит, чинить ли LA-04 и что считать «заявленной ценностью» для компенсации.
3. **Какой набор финансовых данных партнёр имеет право видеть?** Обязателен ли ему экран выплат и кредит-нот (LA-05) и видит ли он сумму «к выплате» vs «оценка»?
4. **Входит ли роль `partner_finance` в релиз?** Сейчас её нет ни в одной персоне, ни в UI, хотя `disputePartnerLine` требует именно её (LA-11). Если роль вводится — нужна ли ей отдельная сессия/экран или хватит прав внутри «Прачечной»?
5. **Продаётся ли внеплановый стоп за +500 ₽?** Если да — где он покупается в флоу заказа (LA-10). Если нет — снимаем обещание с лендинга.
6. **Нужен ли публичному preview ключ доступа?** Сейчас механизм есть в бэкенде, но UI его никогда не показывает, а в dev-режиме ключ не проверяется (LA-16).
7. **Требуются ли серверные черновики ответов поддержки?** (LA-09)
8. **Кому показывать полный телефон клиента в сигнале оттока и в поиске заказов?** Нужен ли аудит этих чтений по 152-ФЗ (LA-13).
9. **Требуется ли офлайн-режим для фото доказательств?** Сейчас офлайн есть для сканов, но не для фото (LA-14).
10. **Кто может закрывать заказ и разбирать застрявшие статусы?** Есть ли у админа эскалация для «зависших» заказов (например, `at_hub` без назначенной фабрики) — сейчас её нет ни в одном маршруте.
