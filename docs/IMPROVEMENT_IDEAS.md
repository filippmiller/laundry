# Тридцать идей улучшения «Чисто»: разбор, отбор и планы

Документ отвечает на исходный запрос: «придумай 30 лучших идей улучшения, оцени каждую
критически, оставь отличные с детальным планом, внедри и задеплой».

Каждая идея получила вердикт из трёх возможных:

- **Оставить** — идея реализуема в этом репозитории, даёт измеримую ценность и не нарушает
  продуктовые договоры (`docs/OPERATING_CONTRACTS.md`).
- **Отклонить** — либо прямо запрещена документами проекта, либо требует внешнего юридического
  или платёжного решения, которое агент не вправе принять за владельца продукта.
- **Отложить** — правильная по сути, но требует работы, которую нельзя довести до конца в этом
  цикле (или которая упирается в отсутствующие в системе данные).

Уверенность — честная оценка вероятности, что идея даст тот эффект, который заявлен.

## Часть 2. Планы по оставленным идеям

Ниже — то, что реально легло в код, с честным «против» и уверенностью.

### 2.1 Дебиторка и кредиторка — `src/services/finance-analytics.ts`

Договорённости по деньгам зафиксированы один раз и используются всеми тремя чтениями:

```ts
 invoiced   = сумма неотменённых счетов
 collected  = captured − refunds
 receivable = max(0, invoiced − collected)
 credit     = max(0, collected − invoiced)
 payable    = max(0, accrued − disputed − paid)
```

Оспоренные начисления в кредиторку не попадают: спор — это не долг.

**Против.** Счёт может быть выставлен, а деньги ещё в эквайринге — «собрано» покажет ноль там, где
деньги уже в пути. Разведено только явной отметкой о возвратах.

**Уверенность: 85%.**

### 2.2 Смесь вещей и веса — `src/services/item-mix.ts`

Поштучный счёт живёт только для «Защищённого» (тариф обещает опись), «Эконом» измеряется весом.
Категория нормализуется через общий словарь `shared/garment-taxonomy.ts` — тот же файл читает
иконографический выбор в вебе, поэтому вещь, выбранная иконкой, и вещь, вписанная руками, попадают
в одну корзину.

**Против.** Старые строки с «Верхняя одежда» схлопываются в «прочее»; сырые значения сохраняются
рядом, чтобы словарь можно было расширять по реальным данным, а не по догадкам.

**Уверенность: 90%.**

### 2.3 Иконографическая сдача и приёмка — `shared/garment-taxonomy.ts`, `apps/web/src/components/garment-icons.tsx`, `apps/web/src/components/GarmentPicker.tsx`

Путь пользователя: иконка семейства → оверлей с подвидами → количество ползунком/колесом →
готово. Ни одного текстового поля для количества.

```tsx
<GarmentPicker
  value={picked}
  onChange={handlePickedChange}
  title="Что приняли"
  renderExtra={item => (
    <span className="garment-row-fields">
      <input type="number" value={itemMeta[item.subtypeId]?.declaredValueRub ?? "5000"} … />
      <input type="text" placeholder="дефекты, если есть" … />
    </span>
  )}
/>
```

Иконки нарисованы вручную (24×24, один штрих, `currentColor`): в `lucide-react` нет одежды,
а эмодзи запрещены `DESIGN.md` и выглядят по-разному на каждой платформе.

Количество задаётся ползунком, чипами 1/2/3/5/10 и колесом мыши по крупной цифре — на улице
одной рукой это самый быстрый жест.

**Против.** Свои иконки — это поддержка: их придётся перерисовывать при смене дизайн-системы.
Список подвидов придётся пополнять вручную, когда прачечная попросит «салфетки» или «шарф».

**Уверенность: 90%.**

### 2.4 Декларация клиента в неизменяемой котировке — `src/domain/pricing.ts`, `src/services/quotes.ts`

Список того, что клиент заявил, попадает в `snapshotJson` котировки, а значит — в её хеш:

```ts
export type QuoteInput = { …; declaredItems?: DeclaredItem[] };
const snapshot = { …, declaredItems: input.declaredItems ?? [] };
return { lines, totalKopeks, quoteHash: hashRequest(snapshot), snapshot };
```

Изменение списка меняет хеш котировки: клиент подтвердил именно этот список. Схема базы не
менялась — декларация едет в уже существующем неизменяемом снимке.

Сервер проверяет подвид по общему словарю и **отказывает** в декларации на тарифе «Эконом»:
поштучный список противоречил бы тому, что клиенту продали.

**Против.** Декларация — это утверждение клиента, а не измерение. Она не является доказательством
и не может быть основанием для списания без согласия.

**Уверенность: 85%.**

### 2.5 Начисления прачечной по договору — `src/services/partner.ts`

```ts
const wholesalePerKgKopeks = Number(contract.termsJson.wholesalePerKgKopeks ?? DEFAULT_WHOLESALE_PER_KG_KOPEKS);
const wholesalePerPieceKopeks = Number(contract.termsJson.wholesalePerPieceKopeks ?? DEFAULT_WHOLESALE_PER_PIECE_KOPEKS);
```

Единица измерения тоже из договора: килограммы для веса, штуки для вещей.

**Против.** Если поле в `termsJson` не заполнено, работает значение по умолчанию — и прачечная
получит начисление по договорённости, а не по подписанному договору. Поэтому демо-сид при
пересеве чинит и договор, и тариф.

**Уверенность: 85%.**

### 2.6 Демонстрационная книга бизнеса — `src/services/demo-book.ts`

14 сценариев через 4 клиентов, проведённые **реальными доменными сервисами** (котировка → заказ →
забронированный слот → назначение курьеру → приёмка → приём прачечной → контроль качества →
доставка → счёт → оплата → возврат → претензия → компенсация → закрытие). Обратной датируются
только презентационные отметки времени; журналы не трогаются.

**Против.** Сид при пересеве обязан быть идемпотентным: ключи идемпотентности выводятся из
идентификатора сценария и окна, а окно заканчивается — поэтому сценарный набор умножается, а не
переписывается. Старый демо-тенант при этом не ломается: сценарий с новым набором данных
получает новый ключ и создаётся рядом.

**Уверенность: 90%.**

## Часть 3. Что не сделано и почему

- **Автосписание расхождения веса** — требует согласия клиента по договору. Считаем, показываем,
  предлагаем — не списываем.
- **Реальная фискализация** — договор с провайдером и подпись владельца продукта.
- **Онтрейнмент вещей (RFID, фото-распознавание)** — цена ошибки: спор о ценности вещи.
- **Динамическая маршрутизация** — нет геокодинга и карт; имитация решения хуже её отсутствия.
- **Микросервисы** — модульный монолит дешевле и надёжнее на текущем масштабе.
- **Уведомление клиенту и QR-квитанция с составом описи** — отложены: нужны канал доставки и
  генерация печатной формы.
