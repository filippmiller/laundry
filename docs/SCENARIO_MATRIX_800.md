# Laundry — 800 сценариев по 16 слайсам

Версия: 2026-11-16. Статус: проектная матрица v1, не подтверждение реализации.

**Метод:** 16 слайсов × 10 конкретных бизнес-действий × 5 режимов проверки = 800 отдельных test cases. Каждый сценарий имеет ID, роль, действие, условие, ожидаемый результат. Пять режимов: A штатно, B некорректные данные, C повторы/гонки, D отказ зависимости, E спор/отмена. Матрица задаёт минимальный контракт тестирования, но не заменяет детализированные Gherkin/Playwright тесты, схемы API и юридическое согласование.

## Обязательные правила для всех 800 кейсов
1. Для каждого действия сохраняются actor, tenant, request_id/idempotency_key, timestamp, исходное и итоговое состояние, version условий и связанный документ/событие.
2. Ошибочные или повторные запросы не должны менять деньги и факты повторно.
3. Внешний вызов не считается успешным до подтверждения; async-операции имеют pending/failed/retry и сверку.
4. Важные изменения (цена, метод обработки, внеплановый слот) требуют согласия и снимка условий.
5. Финансовый ledger отделён от operational status и от расчётов с прачечной.
6. Ошибочные действия не стираются: добавляются коррекции, события расследования и audit trail.
7. Для каждого кейса coding-агент обязан добавить: предусловия fixtures, переходы state machine, API контракт, права доступа, UI state, уведомления, observability и автоматизированный тест.
