## 1. Предмет и границы ревью

**Что проверялось.** Код волны 8 в ветке PR #4 — девять находок и наблюдений повторной
приёмки, два пробела доказательств и одна находка, найденная гейтами самой волны 8, — плюс
пункт «Сохранить принятые исправления» (баланс, уведомления, ценность, worker) из
`04_ACCEPTANCE_RU.md`: ранее принятые исправления не должны быть сломаны волной 8.

**Правило смены вердикта** взято из приёмки дословно: запись в отчёте должна называть code
SHA/tree, ревизию, фактический результат и evidence path; невыполненная запись — `NOT_RUN`,
заблокированная — `BLOCKED`, а не `PASS`.

**Границы.** Ревью ограничено кодом, прогонами и доказательствами. Уровни **DEPLOY** и **LIVE**
не проверялись: Docker в этой среде недоступен, образы не собирались, контейнеры не
поднимались; настоящий worker, реальные SMS/платёжный/фискальный провайдеры и публичный
preview не запускались. CodeRabbit в каждом прогоне CI был **skipped** — внешнего ревью этих
прогонов не существует, и его результатом считать нечего.

## 2. Метод: четыре независимых канала

Ревью не полагалось на один способ проверки — четыре канала давали один и тот же вывод.

1. **Собственное ревью кода и живой приёмки.** Разбор волны 8 по файлам и по истории коммитов;
   пробы приёмки из архива, запущенные против кода этого PR; собственные сценарии на границах
   (гонка загрузки и отправки, связность поколений, полнота выгрузки, полномочия).
2. **Три независимых верификатора** со свежим контекстом и прямым требованием искать обходные
   пути, а не подтверждать отчёт: (а) черновик и список споров, (б) деньги, выгрузка, эскалации,
   (в) доказательства, регрессии и новые правки. Все три вернулись с вердиктом по каждому
   пункту и со ссылками на строки кода.
3. **Пробы приёмки из архива** — как есть (неадаптированная проба контроллера черновика прошла
   без изменений, exit 0) и адаптированные под изменившуюся форму вызова продукта
   (`markSent(threadId, revision)`, новая форма выгрузки, вынесенная логика финансовой панели).
   Адаптации меняли только форму вызова, не сценарий и не данные; они лежат в `temp/` и в
   репозиторий не попадают.
4. **Гейты** — полный набор на тестируемой ревизии: lint, typecheck, тесты, сборка фронтенда,
   клиентский smoke, приёмки волн 6, 7 и 8 (API и браузер), скан маршрутов, мобильная регрессия.

## 6. Независимые вердикты ревьюеров

Три ревьюера со свежим контекстом дали независимые вердикты; расхождений в оценке волны 8 нет.

- **Черновик и список споров:** LND-R5-01, R5-02, R5-03 — закрыты, каждая находка разобрана по
  строкам кода, обходные пути (прямой `DELETE` из интерфейса, чужой тред в `markSent`, кнопка
  «Назад») проверены. Найдено: гонка «позднего ответа» вне списка споров (→ M-1) и остаточный
  черновик после упавшей загрузки (→ L-3).
- **Деньги, выгрузка, эскалации:** LND-R5-04, R5-05, R5-06, R5-07 — закрыты; собственные стресс-
  и браузерные проверки подтвердили полноту выгрузки (1501 сессия), достижимость эскалаций и
  режим просмотра у финансиста. Найдено: гонка в панели аналитики (→ M-1), двойная перезагрузка
  (→ L-1), неограниченные очереди (→ O-1).
- **Доказательства, регрессии, новые правки:** «Сохранить принятые исправления» — выполнено по
  всем четырём пунктам. LND-R5-EV-01 — закрыт для волны 7, **но не для волны 8** (→ M-2);
  LND-R5-DOC-01 — закрыт по кодировке, но отчёт волны 7 не называл tree и CI-прогон (→ L-4).
  Найдено: мобильная проба негерметична (→ M-4), блокировка прокрутки теряет позицию (→ M-3),
  достижимый диапазон восстановления (→ L-2), BOM в CI (→ L-5).

- `lnd-5me` — жизненный цикл публичного демо (публичность, срок жизни, правила сброса
  синтетических данных) и предпосылки пилота.
- `lnd-8ev` — юридические гейты (54-ФЗ/ОФД, потребительский закон, 152-ФЗ, договор с партнёром,
  политика возвратов, объём и сроки хранения выгрузки).
- Остальные вопросы брифа: продаётся ли стоп за +500 ₽, нужен ли публичный preview-ключ, кому
  раскрывать полный телефон.

**Технические долги, заведённые как задачи:** `lnd-evpz` — курсорная пагинация очередей ops;
плюс гонка «позднего ответа» в клиентских, курьерских и административных пространствах (§5, O-2).

**Что по-прежнему не выполнялось и не заявляется:** настоящий контейнерный запуск worker'а
(Docker недоступен); браузерная приёмка настоящих компонентов выполнена для сценариев волны 8,
остальные критерии закрыты unit-тестами и живыми проверками API — в репозитории нет DOM-харнесса.

## 9. Как проверить

```bash
npm run lint            # 0 ошибок
npm run typecheck       # tsc для src и apps/web
npm test                # полный набор: unit + интеграция против PostgreSQL
npm run web:build       # сборка фронтенда
npm run smoke           # scripts/smoke-e2e.mjs
npm run verify:wave6    # живая проверка волны 6
npm run verify:wave7    # живая проверка волны 7 (скрипт сам поднимает сервер)
npm run verify:wave8    # живая проверка волны 8 (API)
npm run verify:wave8:ui # браузерная приёмка настоящих компонентов
npm run verify:routes   # статический скан маршрутов против вызовов из UI
npm run verify:mobile   # мобильная регрессия: 16 комбинаций вьюпорта, зума и роли
```

Приёмки волн 7 и 8 умеют поднимать свой стенд (`VERIFY_SPAWN_API=1`, `VERIFY_SPAWN_APP=1`) —
тогда receipt доказывает идентичность именно того процесса, который отвечал. Без этих флагов
receipt прямо говорит, что идентичность внешне запущенного стенда не доказывается.

Артефакты: receipt'ы — в `docs/evidence/wave7/` и `docs/evidence/wave8/`; отчёт волны 8 —
[`PR4_REMEDIATION_WAVE8_2026-11-27.md`](PR4_REMEDIATION_WAVE8_2026-11-27.md). Старые receipt'ы
не переписаны и остаются артефактами истории.

## 10. Оговорка о вердикте

Вердикт **PASS по CODE и CI** означает: девять находок, два наблюдения, два пробела
доказательств и находка волны 8 закрыты, «Сохранить принятые исправления» выполнено, а
финальное независимое ревью не оставило открытых продуктовых дефектов. Он **не** означает, что
продукт развёрнут, проверен с реальными провайдерами или одобрен владельцем: DEPLOY и LIVE
остаются неподтверждёнными, три решения владельца — открыты, а два технических долга из §8
заведены отдельными задачами.
